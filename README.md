# Career Quest — развитие сотрудников

Существующий интерфейс на HTML/CSS/JavaScript подключён к Node.js backend с SQLite. Профиль, карьерная цель, рекомендации, сессии, пойнты и HR-сводка работают на синтетическом датасете. AI не требуется для расчётов и пока не подключён.

## Запуск backend и существующего фронтенда

Нужен **Node.js 24+**. Внешних npm-зависимостей нет; SQLite и тестовый раннер входят в Node.js.

```sh
git clone https://github.com/BAITC-Hacks/hack-53941d5e-triple-a-solutions.git
cd hack-53941d5e-triple-a-solutions
npm start
```

Без npm можно выполнить:

```sh
node --env-file-if-exists=.env.local src/backend/server.mjs
```

Откройте http://127.0.0.1:4173. Первый запуск проверяет датасет и создаёт `.local/career-quest.sqlite` и `.local/access.json`. В файле доступа находятся два разных случайных ключа: `employeeToken` для личного кабинета и `hrToken` для HR. Введите нужный ключ в форму входа. Не публикуйте этот файл и не передавайте HR-ключ агенту, которому нужен только личный кабинет.

На Windows без Node в PATH можно использовать `scripts/start-backend.ps1`: он найдёт установленный Node или имеющийся runtime Codex. Скрипт не устанавливает программы.

Backend слушает только localhost. Это демонстрационная аутентификация для локального MVP: один настроенный сотрудник и HR, не корпоративный SSO. По умолчанию сотрудник `E0066`. HR читает другие профили только через `/api/hr/*`. Прямой доступ к полному `data.json`, базе и ключам через HTTP закрыт.

## Настройки

Скопируйте `.env.example` в `.env.local`, только если локального файла ещё нет. Не перезаписывайте существующие ключи.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `4173` | Локальный порт |
| `CQ_EMPLOYEE_ID` | `E0066` | Личный кабинет демонстрационного пользователя |
| `CQ_AS_OF` | `2026-10-01` из датасета | Модельная дата для проверки сессий |
| `CQ_DB_PATH` | `.local/career-quest.sqlite` | Отдельная постоянная база |
| `CQ_DATASET` | `src/prototype/data.json` | Объединённый JSON или каталог исходных JSON/CSV |
| `CQ_EMPLOYEE_TOKEN` | Случайный ключ из `.local/access.json` | Переопределение ключа сотрудника |
| `CQ_HR_TOKEN` | Случайный ключ из `.local/access.json` | Переопределение ключа HR |

Будущую сессию нельзя завершить. Для демонстрации всех трёх сессий API Testing запустите **отдельную** базу с `CQ_AS_OF=2026-12-22` и завершайте сессии через каталог. Модельную дату задаёт администратор при запуске, клиент не может её изменить. Нельзя открыть базу с датой раньше уже сохранённых завершений. `completed_at` содержит фактическое серверное время, `date` — модельную дату действия.

PowerShell, отдельное демонстрационное окружение:

```powershell
$env:CQ_DB_PATH = '.local/session-demo.sqlite'
$env:CQ_AS_OF = '2026-12-22'
node src/backend/server.mjs
```

Цели, уровни и начисления переживают обновление страницы и перезапуск. Кнопка «Обновить данные» ничего не удаляет. Для чистого демо укажите новое имя базы. После перезапуска требуется повторный вход.

## Данные и правила

В Git включён только синтетический снимок: 200 сотрудников, 60 навыков, 32 профиля роль × грейд, 40 активностей, 2 743 записи истории. Реальные персональные данные не добавлялись.

```sh
npm run validate
node src/backend/validate.mjs /path/to/career_quest_dataset
```

Каталог исходного набора содержит `employees.json`, `events.json`, `skills.json`, `activity_history.csv`. Валидатор проверяет идентификаторы, ссылки, роли, грейды, навыки, диапазоны, статусы, даты и политику пойнтов; числа из CSV нормализуются. Импорт в новую базу выполняется при старте. HTTP-проверка и импорт доступны HR; обновление набора с уже сохранёнными действиями запрещено, чтобы не потерять прогресс.

Расчёты детерминированы. Рекомендаций не более трёх; если подходящих нет, возвращается пустой список и причина. Допуск определяется текущей ролью, грейдом, prerequisites, датами и историей. Цель не отменяет условия допуска. Изменение цели может изменить процент покрытия, но не уменьшает навыки или пойнты.

```text
after = max(before, min(before + gain, max_level, 5))
coverage = round(sum(min(level, required)) / sum(required) * 100)
```

Пойнты берутся из `src/prototype/demo-rules.json`: курс 4, практикум/менторство 3, сертификация 5, клуб 1, обязательное обучение/онбординг 2. API Testing (`EV_019`) — три сессии по 1 пойнту, прирост навыков только после всех сессий. Повторяемый клуб `EV_036` засчитывается один раз за каждую отдельную сессию. Остальные активности одноразовые. Для обычного курса даты расписания — альтернативные проведения; только явно описанная программа требует все сессии.

Исторические пойнты ретроспективны и помечены `demo-derived`. У исходной истории нет точного `completed_at`; для самостоятельных курсов `date` служит приближением. Завершения до `last_review_date` не добавляют навыки повторно. Повторные обязательные обучения сохраняются в истории, но не дают повторных пойнтов по текущим демоправилам. Историческое завершение программы не означает прохождения её будущих сессий: каталог отмечает `historicalCompletion`.

Пропуски не отнимают навыки и пойнты. Предупреждение появляется только при связи пропущенной активности с оставшимся разрывом цели и возможным приростом этого навыка. Ранжирование учитывает историю формата; это не оценка мотивации. HR-сводка не содержит публичных рейтингов.

## API и примеры запросов

Полный контракт, ошибки и правила для AI-агента: [docs/backend-api.md](docs/backend-api.md).

Пример PowerShell после запуска (ключи читаются локально, не вставляйте их в код):

```powershell
$access = Get-Content .local/access.json -Raw | ConvertFrom-Json
$headers = @{ Authorization = "Bearer $($access.employeeToken)" }
Invoke-RestMethod http://127.0.0.1:4173/api/employees/E0066 -Headers $headers
Invoke-RestMethod http://127.0.0.1:4173/api/employees/E0066/recommendations -Headers $headers
Invoke-RestMethod http://127.0.0.1:4173/api/employees/E0066/goal -Method Put -Headers $headers -ContentType application/json -Body '{"role":"QA Engineer","grade":"Senior"}'
$catalog = Invoke-RestMethod http://127.0.0.1:4173/api/employees/E0066/events -Headers $headers
$item = $catalog.events | Where-Object canComplete | Select-Object -First 1
if ($null -ne $item) {
  $headers['Idempotency-Key'] = [guid]::NewGuid().ToString()
  $body = if ($item.completionSessionId) { @{ session_id = $item.completionSessionId } | ConvertTo-Json } else { '{}' }
  Invoke-RestMethod "http://127.0.0.1:4173/api/employees/E0066/events/$($item.event.event_id)/complete" -Method Post -Headers $headers -ContentType application/json -Body $body
  # При повторной отправке того же действия сохраняйте тот же Idempotency-Key и body.
}
Invoke-RestMethod http://127.0.0.1:4173/api/hr/overview -Headers @{ Authorization = "Bearer $($access.hrToken)" }
```

## Проверки

```sh
npm test
npm run validate
```

Тесты используют синтетические фикстуры, временные базы и встроенный `node:test`: допуск, точный прирост и покрытие, программа из трёх сессий, повторы и конкурентные запросы, сохранение после перезапуска, важные пропуски, HR-доступ и безопасный импорт. Внешних AI API и платных вызовов нет.

## Структура и переиспользование

- `src/prototype/` — прежний интерфейс и исходная модель; `api-client.mjs` связывает его с сервером.
- `src/backend/validate.mjs` — проверка и нормализация JSON/CSV.
- `src/backend/store.mjs` — SQLite и транзакции.
- `src/backend/service.mjs` — серверные правила; переиспользует `createModel` и `applyGain`.
- `src/backend/server.mjs` — HTTP API, авторизация, раздача разрешённых файлов интерфейса.
- `tests/` — исходные тесты прототипа и проверки backend.
- `docs/` — контракт API, описание кейса, решения и демосценарий.

Старый режим прототипа сохранён: `python scripts/preview.py` (Python 3.10+). Он работает без backend и постоянного хранения, с открытым демо-HR. Не запускайте его одновременно с backend на одном порту. Для обновления снимка остаётся `python scripts/prepare-demo-data.py --source /path/to/career_quest_dataset`.

## Совместная версия: карта развития и AI-объяснения

Ветка backend объединяет `codex/employee-navigator` с серверным хранением и интерфейсом пойнтов/сессий. `npm start`, `scripts/start-backend.ps1` и `start-prototype.cmd` запускают один backend, один интерфейс и одну базу. Нужен Node.js 24+.

В личном кабинете появились объяснения рекомендаций и карта развития. Состав и порядок рекомендаций, маршрут, прогноз навыков и даты рассчитываются кодом. AI получает только рассчитанные факты, не имена сотрудников, и может переформулировать объяснение. Подмена состава или порядка приводит к ответу по правилам. Карта — прогноз, а не запись на занятия; выполнение всегда проверяет backend. Для программы прирост наступает только после всех сессий. Завершённые активности не включаются в новый маршрут (в том числе повторяемые клубы: планирование консервативно).

Мастерская HR доступна только HR. Её предложения — редактируемые черновики, которые можно скачать для команды; они не изменяют каталог, приросты или пойнты. Карты и черновики доступны до перезагрузки страницы; фактические цели и прогресс постоянно хранятся в SQLite. После изменения профиля карту нужно перестроить.

Без AI-ключа работают расчёты и шаблонные объяснения. Для необязательных AI-формулировок задайте `OPENAI_API_KEY`, при необходимости `AI_MODEL`, `AI_BASE_URL`, `AI_TIMEOUT_MS` в `.env.local` и перезапустите сервер. `AI_ENABLED=false` выключает вызовы. Ключ не передаётся браузеру и не попадает в Git. Реальные платные вызовы при проверке слияния не выполнялись.

Новые авторизованные маршруты: `GET /api/ai/status`, `POST /api/recommendations`, `POST /api/development-plan`, `GET /api/hr/activity-contexts`, `POST /api/hr/improve-activity`. См. [контракт](docs/backend-api.md). Внутренний `createAppServer` в `scripts/serve.mjs` оставлен для тестов старого прототипа; CLI этого файла запускает защищённый backend.
