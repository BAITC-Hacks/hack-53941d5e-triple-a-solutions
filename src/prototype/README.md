# Career Quest — черновой интерактивный прототип

Локальный макет для знакомства с продуктом. Работают карьерная цель, объяснимые рекомендации, программа API Testing из трёх сессий, пойнты, пересчёт навыков, важные пропуски и отдельная аналитика HR.

## Запуск

Из корня репозитория, Python 3.10+:

```sh
python3 scripts/preview.py
```

Открыть http://127.0.0.1:4173. Пакеты устанавливать не нужно.

Подготовленный синтетический снимок `src/prototype/data.json` уже включён в командный репозиторий. При получении обновлённого набора его можно пересобрать:

```sh
python3 scripts/prepare-demo-data.py --source /path/to/career_quest_dataset
```

Команда не изменяет набор организаторов. Сервер публикует только каталог прототипа и слушает localhost: `.env.local` и прочие файлы репозитория недоступны через него.

## Что попробовать

1. Завершить три сессии API Testing: за каждую начисляется 1 пойнт, а уровень навыка и прогресс к цели меняются после третьей.
2. Открыть причины обычной рекомендации и завершить активность: пойнты, навыки и карьерный прогресс должны пересчитаться один раз.
3. Изменить цель и сравнить важность навыков и рекомендации.
4. Переключиться на обзор HR и открыть детали сотрудника с повторными важными пропусками.
5. Нажать «Сбросить демо» для восстановления исходного состояния.

## Ограничения

- Это **не полное решение хакатона**: AI, импорт дополнительных профилей, авторизация и постоянное хранение ещё не реализованы.
- В исходном наборе нет `points`, правил начисления, отдельной сущности сессии, `session_completed_at`, признака допустимого повторного прохождения и причины пропуска. Временные правила изолированы в `demo-rules.json`; компоненты не содержат чисел начисления.
- Даты трёх сессий API Testing, прирост навыков, максимальный уровень и требования цели берутся из `data.json`. Демонстрационное правило добавляет 1 пойнт за сессию и применяет реальный прирост навыка после завершения всей программы.
- Исторические пойнты рассчитаны ретроспективно по временным правилам и явно помечены в интерфейсе. Для не повторяемых активностей одна и та же активность учитывается один раз; повтор допускается только для `EV_036`.
- Рекомендации детерминированы: фильтры роли/грейда, prerequisites, дат, истории; рейтинг по сокращению пробелов, приоритету критичных навыков, длительности и истории формата. Генеративная модель не вызывается.
- Отсутствующая цель заменяется явно обозначенной предполагаемой целью. Для Lead используется текущая роль и грейд. Смена цели не отменяет допуск по текущей роли/грейду.
- Балл прогресса = сумма покрытых требуемых уровней / сумма требуемых уровней. Это не обещание повышения.
- Последующие завершения применяются после `last_review_date`. Для самостоятельных курсов дата зачисления используется как приближение даты завершения; в исходнике нет `completed_at`. Подробнее: `docs/career-quest-data-review.md`.
- Новое завершение моделируется сразу, даже если сессия в будущем. Действие не меняет реальные записи и работает один раз на шаг; повторное участие учитывается только при явном правиле активности.
- Прогресс и выбранные цели хранятся только в памяти страницы. Обновление страницы сбрасывает их. HR-режим доступен открыто, только для демонстрации синтетических данных.
- Личный кабинет не содержит переключателя на чужой профиль. Индивидуальный контекст других сотрудников показан только в HR-разделе; публичного рейтинга нет.
- Данные не отправляются во внешние API; шрифты и ресурсы локальные.

## Серверный режим

Тот же интерфейс работает с Node.js backend: см. корневой README и docs/backend-api.md. Запуск: npm start (Node.js 24+). В этом режиме цели, навыки и пойнты сохраняются в SQLite, будущие сессии нельзя завершить, HR требует отдельного входа. Описанные выше сброс при обновлении и открытое переключение HR относятся только к старому Python-демо.
