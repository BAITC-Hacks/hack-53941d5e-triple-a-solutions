# AI-подбор Career Quest

## Поведение в интерфейсе

AI встроен в «Мой рост», отдельного чата нет. Страница сразу показывает прежний подбор.
Кнопка «Подобрать с AI» запрашивает персональный выбор. Пока идёт запрос, старые
карточки доступны. Ответ заменяет карточки; «Почему мне?» показывает интерпретацию
AI и конкретные факты. «Сравнить с подбором по правилам» показывает два варианта.
После изменения цели или завершения активности в AI-режиме подбор обновляется.
Сброс демо выключает AI-режим и отменяет ожидающие запросы.

## Настройка и запуск

Нужен Node.js 22+; сторонних зависимостей нет.

1. Скопируйте `.env.example` в `.env.local`, только если файл ещё не существует.
2. Выберите разрешённый организаторами endpoint. Ограничение кейса на передачу
   датасета действует и для синтетических профилей. Не включайте внешнюю отправку
   без разрешённого для хакатона способа использования данных.
3. Заполните `AI_MODEL`, `AI_BASE_URL` и при необходимости `OPENAI_API_KEY` локально.
   Реализован протокол **Responses API с strict JSON Schema**. Произвольный
   Chat Completions endpoint не совместим без отдельного адаптера.
4. После проверки разрешений установите `AI_ENABLED=true`, `AI_DATA_APPROVED=true`.
5. Запустите `node scripts/serve.mjs` и откройте http://127.0.0.1:4173.
   После изменения `.env.local` перезапустите сервер.

Для внешнего endpoint требуется HTTPS; HTTP разрешён только для localhost.
Ключ не обязателен у локального провайдера, если его сервер не требует авторизации.
Название модели намеренно не зафиксировано: нужны доступная вашей команде модель
и совместимость с указанным протоколом. Настройки или отсутствие ключа в браузер не передаются.
API статуса возвращает только доступность и пояснение; AI-ответ содержит имя модели.

## Границы ответственности

- `src/prototype/model.mjs` — общий для браузера и сервера расчёт допустимости и прогресса.
- `scripts/ai/system-prompt.txt` — роль, критерии выбора, ограничения и работа с фактами.
- `scripts/ai/recommender.mjs` — подготовка данных, запрос, валидация, кеш и резервный режим.
- `scripts/serve.mjs` — сервер: `GET /api/ai/status`, `POST /api/recommendations`.
- `src/prototype/ai-client.mjs` — ожидание ответа отдельно для каждого состояния профиля.

Браузер отправляет ID сотрудника, выбранную цель и демо-завершения. Сервер строит
контекст заново из своего датасета. Клиент не может подменить вычисленные навыки
или прислать произвольный prompt. В модель уходят роль, грейд, цель, допустимые
курсы, ожидаемый прирост и агрегаты истории типа/формата; ФИО, email, ID сотрудника
и полный датасет не отправляются. Это минимизация данных, а не гарантия анонимности.
Все допустимые кандидаты передаются по ID, без баллов исходного алгоритма.

AI реально выбирает и ранжирует события, а не только переписывает готовую тройку.
Сервер проверяет допустимые ID, отсутствие повторов и ссылки на три категории
фактов: цель, навыки, история. Прирост навыков всегда рассчитывает код.
**Свободный текст пояснения не проходит полную смысловую проверку**: корректные
ссылки не исключают неверную интерпретацию. Перед защитой требуется ручная оценка.

Запрос использует `store:false`; это не отменяет условия обработки данных провайдера.
Таймаут по умолчанию 8 секунд; интерфейс ждёт максимум 10 секунд. Эти ограничения
не являются результатом замера реальной модели. Успешный результат кешируется
на 5 минут по содержимому профиля, цели, кандидатов, версии prompt и имени модели.
Повторные одновременные запросы объединяются. Не больше трёх разных запросов одновременно.
При ошибке, отказе, неподходящем JSON или таймауте возвращается **подбор по правилам**
с явной пометкой. Сервер не выдаёт заглушку за AI.

Сервер слушает только localhost, отдаёт только разрешённые файлы интерфейса и
отклоняет запросы с посторонних Origin/Host. Это локальное демо, не замена
авторизации сотрудник/HR. Завершения по-прежнему хранятся только в памяти страницы.

## Проверка качества

```sh
node --test --test-isolation=none tests/prototype.test.mjs tests/ai.test.mjs
node scripts/evaluate-ai.mjs
```

Вторая команда не вызывает модель. Она проверяет исходный алгоритм на семи
придуманных сценариях и считает покрытие кандидатов на 200 исходных профилях.
После настройки разрешённого провайдера:

```sh
node scripts/evaluate-ai.mjs --live
```

Выполняется до шести платных запросов на придуманных сценариях (для пустого
набора кандидатов вызов не нужен). Исходные профили организаторов этот скрипт
модели не передаёт. Отчёты: `artifacts/ai-evaluation.json` и `artifacts/ai-evaluation.md`.
Папка исключена из Git. Сохраняются оба выбора, объяснения, модель, версия prompt,
время ответа и метрики: ожидаемый первый шаг, прирост покрытия, критичных навыков,
длительность, прошлые неуспешные участия в похожем формате.

Ожидания в `tests/fixtures/recommendation-cases.mjs` — наши проверяемые продуктовые
гипотезы, **не экспертная разметка и не официальные проверочные профили жюри**.
Улучшение одного показателя не доказывает улучшение рекомендации. Сравнивайте
парные результаты, ошибки, ухудшения и объяснения. Проверка не измеряет реальный
рост навыков, вовлечённость или успешность повышения сотрудника.

До реального запуска модели вывод об улучшении AI делать нельзя. В первой
проверке интеграции используются явно обозначенные ответы тестового транспорта.
