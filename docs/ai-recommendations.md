# AI-помощник Career Quest

## Подключение и проверка

Node.js 22+, без установки пакетов: `node scripts/serve.mjs` или `start-prototype.cmd`.
Откройте http://127.0.0.1:4173.

В корне репозитория откройте `.env.local` (если нет — скопируйте `.env.example`).
Заполните только `OPENAI_API_KEY=ваш_ключ`, сохраните и обновите страницу.
По умолчанию используются `gpt-4.1-mini` и `https://api.openai.com/v1`.
Сервер перечитывает файл при запросах: перезапуск и изменение кода не нужны.
Проекту ключа нужны доступ к модели и квота API. Ключ хранится только на сервере;
`.env.local` исключён из Git и не отдаётся браузеру.

Добавление ключа включает отправку контекста при нажатии кнопок AI и обновлении
подбора после действий в уже включённом AI-режиме. Используйте разрешённого
правилами хакатона провайдера для этих данных. `AI_ENABLED=false` отключает вызовы.
Для другого провайдера можно задать `AI_MODEL` и `AI_BASE_URL`; нужен Responses API
со strict JSON Schema, одного Chat Completions недостаточно. Внешний адрес должен
использовать HTTPS, локальный может использовать HTTP без ключа.
Старый параметр `AI_DATA_APPROVED` больше не используется.

Статус «настройки готовы» показывает наличие конфигурации. Реальное подключение
проверяется первым запросом. При неверном ключе, квоте, таймауте или невалидном
ответе показывается объяснение и результат по правилам. Без ключа внешних вызовов нет.

## Три функции

### Подбор следующего шага

«Подобрать с AI» выбирает до трёх проверенных активностей. «Почему мне?» показывает
объяснение и факты: цель, навыки и историю. «Сравнить с подбором по правилам» — оба
варианта. Поздний ответ не заменяет рекомендации другого состояния профиля.

### Карта развития сотрудника

Фокус на навыке или всей карьерной цели, 1–20 часов в неделю, до пяти шагов.
Приложение строит несколько маршрутов, проверяя текущую роль, грейд, завершения,
prerequisites, потолки навыков и расписание. Следующий шаг начинается не раньше
расчётного конца предыдущего. AI выбирает маршрут и объясняет порядок; изменить
ID, порядок шагов и числовой прирост он не может.

Карта показывает ожидаемый рост «статов», покрытие требований, оценку сроков и
оставшиеся пробелы. Завершить в демо можно очередной квест; затем открывается
следующий. Изменение цели или постороннее завершение может потребовать пересчёта.
Время — оценка нагрузки, не бронирование. Проценты — покрытие требований,
**не вероятность повышения**. Должность автоматически не меняется.

Поиск ограниченный (beam search), глобальный оптимум не гарантируется. Используется
существующий каталог, шаги для цели и подготовительные курсы по недостающим prerequisites,
в том числе по навыкам вне требований целевой роли. Подготовительный шаг можно пройти
в демо; его прирост показывается отдельно даже без увеличения покрытия цели.
Маршруты, состоящие только из подготовки без шага для цели, не предлагаются. Допуски относятся к текущей роли и грейду,
включая планы перехода в другую профессию.

### Мастерская HR

HR выбирает добровольную активность и описывает задачу. AI получает программу,
агрегаты аудитории/истории и распространённые пробелы. Предлагает конкретные
изменения с основаниями, упражнения, обратную связь, критерии оценки и план пилота.
Учебные блоки должны укладываться в исходное время активности.
Агрегаты учитывают текущие цели и демо-завершения в этом браузере. Сервер заново
восстанавливает их из допустимых ID, не доверяя присланным числам. Сохранённый черновик
содержит факты на момент расчёта; при изменении состояния появляется предложение
создать новый. Перезагрузка с тем же прогрессом не делает черновик устаревшим.

Название, объяснение, изменения, критерии, упражнения, время и пилот редактируются.
Черновик сохраняется в браузере; JSON можно скачать для команды. Без ключа это
явно обозначенный шаблон по правилам: свободное пожелание HR он не интерпретирует.
Повторная генерация заменяет черновик выбранной активности.

Предложение не меняет каталог, gain/max_level и навыки сотрудников. Новые темы
остаются предложениями. Эффективность требует пилота; пропуски не раскрывают
причины и мотивацию. Рейтинга людей нет.

## Хранение и ограничения

Цели, демо-завершения, планы и сохранённые черновики хранятся в localStorage этого
браузера и адреса. Между ноутбуками не синхронизируются. «Сбросить демо» очищает их.
При изменении датасета старое состояние игнорируется. Если браузер блокирует
хранение, появляется сообщение. Числовые проекции сохранённого плана заново
рассчитываются из исходных данных.

Это локальное демо: сервер слушает localhost, экраны HR открыты без авторизации.
Отдаются только разрешённые файлы; посторонние Origin/Host отклоняются. Это не
общая база подтверждённых результатов обучения и не полноценная защита ролей.

В AI не передаются ФИО, email, ID сотрудника или полный датасет. Для подбора/плана
передаются роль, грейд, цель, кандидаты, расчётный прирост и агрегаты истории;
для HR — активность, агрегированные факты и пожелание HR. Не вводите в пожелание
персональные данные. Минимизация контекста не гарантирует анонимность.
`store:false` не отменяет условия обработки данных провайдера.

Один транспорт обслуживает все функции. Таймаут по умолчанию 8,5 секунды (максимум
9), интерфейс ждёт 10–11 секунд. Успех кешируется на 5 минут по задаче, prompt,
данным, схеме, модели и настройкам; одинаковые запросы объединяются. Одновременно
выполняются максимум три разные задачи. В первом реальном прогоне gpt-4.1-mini
ответила за 3,7–6,6 секунды на вымышленных данных; это не гарантия задержки других запросов.
Схема и корректные ссылки не заменяют смысловую проверку свободного текста человеком.

## Файлы и API

- `scripts/ai/provider.mjs`: ключ, Responses, таймаут, кеш, резервный режим.
- `scripts/ai/recommender.mjs`, `system-prompt.txt`: подбор и факты.
- `scripts/ai/workflows.mjs`, `plan-prompt.txt`, `hr-prompt.txt`: план, HR, валидаторы.
- `src/prototype/development.mjs`: маршруты и агрегаты HR.
- `src/prototype/workshop-ui.mjs`, `local-progress.mjs`: интерфейс и сохранение.

Импорт профилей и истории: [формат и инструкция](jury-import.md). Версия набора
передаётся в запросах всех трёх AI-функций; устаревшей вкладке предлагается обновиться.

API: `GET /api/ai/status`, `POST /api/recommendations`,
`POST /api/development-plan`, `POST /api/hr/improve-activity`.
Сервер восстанавливает профиль из employeeId, цели и допустимых демо-завершений.

## Проверки

```sh
node --test --test-isolation=none tests/prototype.test.mjs tests/ai.test.mjs tests/development.test.mjs tests/import.test.mjs
node scripts/evaluate-ai.mjs
```

31 тест: допуски на 200 профилях, prerequisites, расписание, потолки навыков,
фокус/нагрузка, валидаторы AI, HR-основания/время, режим без ключа, горячее чтение
конфигурации, HTTP и восстановление прогресса; импорт, конфликты, версии, перезапуск
и отмена; подготовительный навык вне цели и актуальные HR-агрегаты. Транспорт явно имитируется тестовыми
ответами, внешние вызовы не нужны.

Для экономной проверки трёх AI-функций:

```sh
node scripts/check-ai-workflows.mjs
node scripts/check-ai-workflows.mjs --live
```

Первая команда проверяет режим без модели и ничего не отправляет. Вторая делает ровно
три последовательных запроса на вымышленных данных: подбор, карта развития, мастерская HR.
Для настоящего провайдера нужен ключ/квота. Отчёт `artifacts/ai-workflows-live.json` содержит
источник результата, задержку, валидность и ответы для ручного просмотра. `liveVerified`
будет true только при трёх ответах AI, прошедших проверки и занявших менее 10 секунд каждый.
Отсутствие ключа, возврат к правилам или неуспех дают ненулевой код завершения.
Ключ не «расходуется»: расходуются токены платных запросов. Один ключ можно использовать
повторно; кеш уменьшает повторные вызовы, но не заменяет квоту. Три проверки подтверждают
работоспособность подключения, а не улучшение рекомендаций или результата обучения.

На [официальном сайте HackAlem](https://hackalem.ai/) указаны OpenAI как партнёр и
обязательное использование Codex. Это не отдельное разрешение выносить данные конкретного
кейса. В Career Quest сказано, что данные не выносятся за пределы хакатона. Уточните у
куратора, разрешена ли отправка обезличенных полей в OpenAI API/Sandbox. До уточнения
используйте вымышленные примеры. Контакт организаторов на сайте: team@baitc.org.

`evaluate-ai.mjs` проверяет исходный подбор на семи придуманных сценариях.
`node scripts/evaluate-ai.mjs --live` после подключения делает до шести платных
запросов на этих сценариях, не передавая профили организаторов. Отчёты сохраняются
в `artifacts/ai-evaluation.json` и `.md`, не входят в Git.

Ожидания — наши продуктовые гипотезы, не экспертная разметка. [Первая реальная
проверка трёх функций](ai-live-check-2026-09-23.md) прошла технически, но ручной просмотр
выявил необоснованные формулировки в подборе и пропущенное условие допуска в HR-пилоте.
Перед защитой проверьте пояснения, соответствие пожеланию HR, разумность упражнений,
доступность маршрута и задержку на дополнительных вымышленных сценариях. Улучшение качества рекомендаций от
реальной модели и педагогическая эффективность в этой версии **ещё не измерены**.
