# AI в объединённой версии

Актуальный запуск описан в корневом README, API — в backend-api.md.

`scripts/ai/provider.mjs` переиспользован из ветки employee-navigator: структурированный ответ, таймаут, ограничение параллельных запросов, кеш и fallback. `src/backend/workflows.mjs` подключает его к фактам SQLite. Модель не выбирает рекомендации или маршрут: код передаёт фиксированный набор и порядок, валидатор отклоняет изменения. Имена и идентификаторы сотрудников в AI-payload отсутствуют.

`OPENAI_API_KEY` хранится только в `.env.local`. Настройки читаются при запуске backend; после изменения перезапустите его. Без ключа функции работают по правилам. Наличие ключа ещё не подтверждает доступность модели.

Старые фикстуры `tests/ai.test.mjs`, `tests/development.test.mjs` и оценочный скрипт описывают автономные инструменты прототипа. Ограничения объединённого HTTP API отдельно проверяются в `tests/integration.test.mjs`. CLI `scripts/serve.mjs` теперь запускает общий backend с авторизацией, а не старый автономный сервер.

Планировщик также строит подготовительные шаги для недостающих prerequisites вне требований цели. Маршруты только из подготовки без целевого результата не предлагаются. При смене набора интерфейс перезагружается; версия набора проверяется сервером.
