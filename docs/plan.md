# План команды

До объявления задания готовим репозиторий и выясняем ограничения.
Пользователь подтвердил лимит пять часов после объявления задания; отсчёт ещё не начался. Точное время сдачи пока неизвестно.
Ниже план на 300 минут с момента старта; если часть времени уже прошла, пересчитать по оставшемуся времени, сохранив резерв на сдачу.

| Этап | Минуты от старта | Результат | Ответственный / статус |
| --- | --- | --- | --- |
| Разбор кейса и выбор | 0–20 | Заполненный brief, один сценарий, метрика | Команда / ожидает |
| Проверка главного риска | 20–45 | Реальный пример данных и работающий критический вызов | Участник 1 + Codex / ожидает |
| Сквозной MVP | 45–180 | Сценарий выполняется от ввода до результата | Участник 1 + Codex / ожидает |
| Проверка качества | 180–240 | Набор примеров, измерение, обработка ошибок | Участник 2 + Codex / ожидает |
| Демо и сдача | 240–300 | README, показ, артефакты и отправка | Вся команда / ожидает |

Если главный риск не снят на втором этапе, сокращаем сценарий или меняем вариант.
После появления сквозного MVP новые функции добавляем только ради требований или выявленных проблем.

## Распределение для команды из трёх начинающих

- Участник 1 работает с Codex и запускает продукт. Codex реализует код и технические проверки.
- Участник 2 параллельно собирает 5–10 примеров, ожидаемые результаты и проверяет реализацию как пользователь.
- Участник 3 с первого часа готовит историю показа и материалы; затем репетирует демо и проверяет комплект сдачи.

Это роли, а не обязательный состав; один человек может совмещать несколько.
При каждом завершённом шаге обновляем `progress.md` и делаем осмысленный коммит.

## Ограничение объёма

По умолчанию один экран и один основной процесс. База данных, авторизация, дополнительные агенты и интеграции добавляются только при необходимости для задания. До разработки проверить доступ к нужному API. К третьему часу нужен работающий результат; в последний час — исправления и сдача.
