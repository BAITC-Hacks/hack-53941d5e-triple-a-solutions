# Подключить ключ и проверить AI

1. Откройте [API keys в OpenAI Platform](https://platform.openai.com/api-keys).
   Выберите проект команды/хакатона, если вам предоставлен такой доступ, и создайте
   секретный API-ключ. Проекту нужны доступ к `gpt-4.1-mini` и доступная квота API.
   Не присылайте ключ в чат, не вставляйте в код и не публикуйте в GitHub.

2. В папке прототипа найдите файл `.env.local` рядом со `start-prototype.cmd`.
   Откройте его в Блокноте. Если файла нет, скопируйте `.env.example` и назовите копию
   `.env.local` — без расширения `.txt`. Существующий файл заменять целиком не нужно.

3. Найдите строку `OPENAI_API_KEY=`. Сразу после знака `=` вставьте свой ключ:

   ```dotenv
   OPENAI_API_KEY=вставьте_сюда_свой_ключ
   ```

   Это пример: слова `вставьте_сюда_свой_ключ` нужно заменить целиком.
   Сохраните файл сочетанием Ctrl+S. Модель и адрес API уже настроены.
   Если в файле есть активная строка `AI_ENABLED=false`, поменяйте её на
   `AI_ENABLED=true`. Строки, начинающиеся с `#`, являются комментариями.

4. В Проводнике запустите двойным щелчком **check-ai.cmd**.
   Если открывается его текст, запустите файл именно из Проводника.
   Скрипт сам найдёт Node.js, прочитает `.env.local` и последовательно проверит
   подбор активности, план развития и мастерскую HR. Работающий сервер для этой
   проверки не нужен. На корректно настроенном подключении выполняются три вызова
   модели на вымышленных примерах. Профили организаторов/жюри не загружаются.

5. Успешный результат: `liveVerified: true`, три строки `source: "ai"` и
   `passed: true`. В конце появится «Проверка пройдена». Ответы и задержки сохранены
   в `artifacts/ai-workflows-live.json`, исключённом из Git. Проверьте также смысл
   объяснений и предложений — автоматическая проверка структуры не гарантирует
   педагогическую пользу или правильность каждого утверждения.

6. Обновите страницу прототипа (Ctrl+R). Сервер читает ключ при запросах,
   перезапускать его не нужно. После разрешения на использование данных кейса
   проверьте кнопки «Подобрать с AI», «Создать план» и «Предложить улучшения».
   Ответ модели отмечается как «С помощью AI» / «AI выбрал…». Сообщение
   «По правилам» означает резервный алгоритм, а не успешный ответ модели.

## Если проверка не прошла

| Сообщение | Что проверить |
| --- | --- |
| `live-blocked`, AI ждёт подключения | Ключ вставлен и файл сохранён именно как `.env.local`, не `.env.local.txt`. |
| Сервис AI отклонил ключ | Правильный ли ключ, не отозван ли он. При необходимости создайте новый в своём проекте. |
| Ограничение запросов или квоты | Доступный баланс/кредиты и лимиты проекта. Если это проект хакатона, уточните квоту у организаторов. |
| Модель недоступна | Есть ли у проекта доступ к настроенной `gpt-4.1-mini`. |
| AI не успел ответить | Интернет и задержку провайдера. Тест ждёт до 8–9 секунд на ответ; повторный запуск делает новые запросы. |
| Ответ не прошёл проверку | Пришлите сообщение об ошибке и отчёт на вымышленных данных, без ключа. Нужно проверить совместимость/ответ модели. |

Фраза «Настройки AI готовы» в интерфейсе означает наличие конфигурации, а не
успешный ответ модели. Ключ многоразовый; расходуется квота запросов/токенов.
До разрешения куратора на отправку данных Career Quest используйте проверку
на вымышленных примерах из `check-ai.cmd`.

Официальные источники: [создание и использование ключа](https://developers.openai.com/api/docs/quickstart),
[возможности и лимиты GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).
