# Импорт синтетических данных в объединённый backend

Войдите с HR-ключом и откройте «Данные жюри». Используйте только синтетические профили и историю. Примеры — `data/examples/jury-employees.json` и `jury-history.csv`.

Файлы сначала проверяются без изменения базы. После просмотра списка изменений нажмите «Применить импорт». Перезагрузка интерфейса получит актуальную версию набора. Данные, профильные уровни и предыдущий набор для отмены записываются одной SQLite-транзакцией. После перезапуска отмена остаётся доступной.

Если сотрудник уже завершал активности или менял цель, применение и отмена возвращают 409. Это сохраняет его прогресс; для отдельного демо укажите новое имя базы в `CQ_DB_PATH`. Каталог навыков, активностей и требований не меняется через этот экран. Отсутствующая department обозначается «Не указано». Остальные поля проверяются общим валидатором backend.

HR-маршруты: `GET /api/dataset`, `POST /api/import/preview` с `{version,files:[{kind:"employees"|"history",name,text}],replace?}`, `POST /api/import/commit` с `{version,token}`, `POST /api/import/undo` с `{version}`. Токен предпросмотра действует 10 минут; устаревшая версия отвергается. Личный кабинет не позволяет переключаться на чужие профили; импортированные сотрудники доступны через `/api/hr/employees/:id`.

Профили: JSON-массив, один объект или объект с employees. Обязательны employee_id, role, grade, skills, last_review_date. История: JSON либо UTF-8 CSV с record_id, employee_id, event_id, date, status. ID навыков и активностей должны существовать; уровни 0–5; даты не позже среза. Максимум 1000 сотрудников, 20000 записей истории, 5 МБ файлов. Сам импорт AI не вызывает.

`scripts/import-data.mjs` переиспользован как чистый парсер и валидатор. Старый файловый `scripts/dataset-store.mjs` оставлен для автономных тестов прототипа; рабочее приложение использует `src/backend/imports.mjs` и SQLite.
